      AUTOMATIC SOURCE CHECKS

      Checks start without a repair form.

      Completed CI, Pages and research workflows trigger a bounded check. Trusted mechanical repairs can be applied automatically and the website can be republished when delivery needs recovery. A healthy check records that no repair was needed.

      For other supported source issues, Gemini prepares a candidate and WAKE tests it in isolation. A passing candidate opens a draft pull request for review. Model-authored source changes still need approval before they are merged.

      To request an extra check, open WAKE — Source self-correction, choose Run workflow on master, and leave the optional repair fields blank. GitHub requires repository permission to start a workflow.

      Advanced: request a specific source repair

      Optionally enter one concrete problem and expected behavior in request, then list one to four existing files in paths, separated by commas. Supported model proposals cover wake/assets/*.js, *.css, *.html and docs/*.md.

      Example request

      Fix the ant-farm zoom controls so a two-finger pinch magnifies the habitat around the midpoint of the gesture. Preserve saved colonies, one-finger panning, and keyboard zoom.

      Example paths

      wake/assets/ant-farm.js, wake/assets/ant-farm.css

      WAKE sends the bounded request and selected source to Gemini, validates the edits, and tests them in a separate container with no credentials or network. Review the proposed files and linked checks on the draft branch before merging. Failed attempts retain their logs and any proposal artifact.

      Model proposals use the repository’s existing GEMINI_API_KEY Actions secret and GitHub’s permission for Actions to create pull requests. Requests, proposal artifacts and branches are public; do not include secrets. This page never receives credentials or submits a privileged command.

      THE CHANGE BOUNDARY

      What can change, and what cannot

      Trusted automation owns its narrowly defined mechanical repairs and website republishing. The model can propose changes only within its bounded source allowance. It cannot edit the kernel, governance, authority records, provider credentials, dependencies, tests, deployment bindings or the workflow. Its evaluator is installed code, outside that allowance.

      The native policy lane can change only its installed context-selector setting after its own evidence checks. Neither lane can erase earlier receipts, count its own changes as research progress, change spending limits or grant itself broader permission.

      Review does not require you to copy code by hand: the proposed files are already on the draft branch. Broader runtime self-modification needs a separately versioned capability and compatible runtime release.
